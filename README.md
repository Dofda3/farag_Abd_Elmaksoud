# جزارة فرج عبدالمقصود — متجر ثابت

متجر عربي ثابت ومتجاوب على GitHub Pages. يتصفح العميل الأقسام، يبحث عن الأصناف، يضيف الكميات إلى سلة محفوظة على جهازه، ثم يراجع رسالة الطلب قبل فتح واتساب. لا يوجد دفع إلكتروني. Supabase مستخدم للقراءة والإدارة.

## ملفات المشروع

- `index.html`, `styles.css`: الواجهة العربية RTL وتجربة الجوال.
- `data.js`: أقسام وأصناف تجريبية، بينها صنف أحجام؛ الأسعار للعرض فقط ويجب تحديثها قبل النشر.
- `config.js`: بيانات المتجر ومناطق التوصيل ورسومها.
- `app.js`: قراءة Supabase، البحث والسلة والتحقق من البيانات وتجهيز رسالة واتساب.
- `supabase.sql`: إنشاء الجداول وسياسات RLS والتخزين والبيانات التجريبية.
- `supabase_migration_sizes.sql`: ترحيل آمن للمنتجات إلى طرق البيع بالوزن/الحجم/القطعة، وجدول الأحجام وسياساته.
- `supabase_migration_store_images.sql`: تجهيز bucket الصور للقراءة العامة والرفع للمشرفين فقط.
- `admin.html`, `admin.js`, `admin.css`: لوحة تحكم `/admin.html` للمشرف المعتمد. جميع ملفات الموقع في المجلد الرئيسي.
- `favicon.svg`, `404.html`, `CNAME`, `manifest.webmanifest`, `robots.txt`, `sitemap.xml`: ملفات النشر والاكتشاف.

## إعداد Supabase

1. أنشئ مشروعاً مجانياً في [Supabase](https://supabase.com/)، وانتظر حتى يكتمل تجهيزه.
2. افتح **SQL Editor > New query**، والصق محتوى `supabase.sql` كاملاً ثم اختر **Run**. يجب تشغيل هذا الملف قبل فتح المتجر أو لوحة الإدارة؛ من دونه لن توجد جداول القراءة.
3. شغّل `supabase_migration_sizes.sql` في استعلام جديد على قاعدة البيانات الحالية. يضيف عمود `sale_type` افتراضياً `weight` لكل الأصناف الموجودة، وينشئ `product_sizes` وRLS ودالة حفظ أسعار الأحجام، ويضيف صنف حواوشي تجريبياً بأحجامه. يمكن إعادة تشغيل الترحيل بأمان.
4. شغّل `supabase_migration_store_images.sql` في SQL Editor لتجهيز تخزين الصور وصلاحياته. لا تغيّر إعدادات RLS إلى صلاحيات كتابة عامة.
5. من **Project Settings > API** انسخ **Project URL** و**anon / publishable key** فقط. لا تضع `service_role` key في الموقع.
6. أدخل القيمتين في `supabaseUrl` و`supabaseAnonKey` في `config.js`. هذه بيانات عميل عامة؛ حماية الكتابة تعتمد على RLS وليس على إخفاء anon key.
7. أنشئ مستخدم المالك من **Authentication > Users > Add user** ببريد وكلمة مرور قويين. انسخ UUID للمستخدم، ثم شغّل في SQL Editor (استبدل UUID):

   ```sql
   insert into public.admin_users (user_id)
   values ('00000000-0000-0000-0000-000000000000');
   ```

8. حدّث صف `shop` في جدول `settings` من **Table Editor** لاسم المحل وعنوانه وساعات العمل ومناطق التوصيل وأسعارها. حدّث الأسعار التجريبية في `products` و`product_sizes` قبل فتح الطلبات.
9. حدّد صلاحية المشرف بإضافة UUID مستخدمه إلى `admin_users`. افتح `/admin.html` وسجّل الدخول بنفس البريد وكلمة المرور؛ لا يوجد تسجيل عام للمستخدمين.
10. عند تفعيل إعدادات Supabase، يقرأ المتجر الأصناف والإعدادات مباشرة. إذا فشل الاتصال أو كانت الإعدادات ناقصة، تظهر رسالة صريحة ويتوقف إرسال الطلبات بدلاً من استخدام بيانات بديلة بصمت.
11. لوحة الإدارة تتيح إدارة الأصناف والأقسام، الرفع المضغوط للصور، تعديل الأسعار دفعة واحدة، ومعلومات المحل. حفظ الأسعار والترتيب يستخدم دوال `update_product_prices` و`update_size_prices` و`update_category_order` في SQL.

## الصور

كل صور المحل قابلة للتعديل من تبويب **إعدادات المحل** في لوحة الإدارة: الشعار، غلاف الرئيسية، صورة داخل المحل، الواجهة، وصورة الجزار. ارفع الصور واحفظ الإعدادات؛ تُخزّن الملفات في bucket `product-images` وتُحفظ روابطها في `settings.value.store_images`. صور الأقسام والأصناف تُرفع بالطريقة نفسها من نماذجها، وتُحفظ روابطها في `categories.image_url` و`products.image_url`. لا يحتاج المشروع إلى مجلد صور محلي. عند حذف صورة أو غيابها يظهر بديل مناسب؛ صورة الجزار اختيارية.

## GitHub Pages والنطاق المخصص

ارفع ملفات المشروع إلى مستودع GitHub، ثم من **Settings > Pages** اختر الفرع ومجلد النشر الجذر. الصور لا تُرفع إلى GitHub؛ تدار من Supabase Storage. لموقع مستخدم على نطاق `USERNAME.github.io` يكون رابط sitemap هو `https://USERNAME.github.io/`؛ أما مستودع مشروع فيكون `https://USERNAME.github.io/REPO/`. حدّث الروابط التجريبية `USERNAME/REPO` في HTML و`manifest.webmanifest` و`robots.txt` و`sitemap.xml`.

لنطاق مثل `example.com`:

1. اكتب `example.com` في `CNAME` ومن **Settings > Pages > Custom domain**.
2. في DNS أضف سجلات A للجذر: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
3. أضف CNAME للاسم `www` يشير إلى `USERNAME.github.io`، واضبط تحويل النطاق المفضل من GitHub Pages.
4. انتظر انتشار DNS ثم فعّل **Enforce HTTPS** من صفحة Pages. حدّث رابط sitemap ليستخدم النطاق النهائي.

## المرحلة الأولى واختبار الطلب

عند ترك حقلي Supabase فارغين، يستخدم الموقع بيانات العرض الثابتة ويظهر تنبيهاً واضحاً بأن الأسعار تجريبية. رقم واتساب الحالي هو الرقم الذي زودني به صاحب المتجر. حدّث `data.js` أو قاعدة البيانات، والعنوان ومناطق التوصيل ورسومها في `config.js` أو صف `shop`، ثم اختبر طلب توصيل وطلب استلام على هاتف. تحقق من الاسم ورقم مصري صالح والعنوان والرسوم ورسالة واتساب قبل نشر الموقع للعملاء.

الوزن في الموقع يباع بخطوة ثابتة مقدارها ربع كيلو. حدّد طريقة بيع كل صنف من لوحة الإدارة؛ صنف الحجم يحتاج حجمين على الأقل. عنوان المحل ومواعيد العمل ومناطق التوصيل والأسعار في بيانات seed أمثلة تحتاج إلى تأكيد صاحب المحل. بيانات Supabase الموجودة في `config.js` هي Project URL وpublishable key عامة فقط؛ لا تضع `service_role` key في ملفات الموقع.
